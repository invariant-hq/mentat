Maintain the session task board: the call replaces the whole board with the
list you give, so include every task you still want and omit the ones to drop.
Statuses are pending, in_progress, completed, cancelled; keep exactly one task
in_progress at a time.

Use the board for work of more than a couple of steps, or when the user gave
several tasks or an explicit list. Update it in real time — mark a task
in_progress before you start it and completed the moment it is done and
verified, one at a time rather than in a batch at the end. Do not mark a task
completed while its build is red, its tests fail, or the work is partial;
leave it in_progress and add a follow-up task instead.

Skip the board for a single-step task or a pure question — tracking it is
overhead with no payoff.

This board is the ephemeral plan for the current stretch of work. It is not
the approval gate (propose_plan) and not a long-horizon objective.
